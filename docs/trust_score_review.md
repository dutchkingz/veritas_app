# Trust Score System Review & Redesign

**Date:** 2026-05-03
**Status:** Implemented

---

## Problems Identified

### 1. Vibes-based scoring (no reproducibility)

Both Analyst and Sentinel agents produced a 1-100 trust score based on vague instructions like "consider source reputation, language objectivity, evidence cited." No rubric, no defined deductions — two runs of the same article could produce wildly different scores with no way to audit why.

### 2. Circular source credibility

`SourceCredibilityService` computed a rolling average of trust scores that were themselves generated by LLMs evaluating those same sources. If the LLM overrated a source initially, the EMA (alpha=0.1) made that error extremely sticky — it would take dozens of articles to correct.

### 3. Threat level penalized legitimate coverage

The credibility formula was:
```
(trust x 0.5) + (anomaly_inv x 0.25) + (threat_balance x 0.25)
```

`threat_balance` = `low_threat_count / total_articles`. This means a war correspondent covering genuine conflicts would score lower on credibility simply for covering high-threat topics. Threat level is an attribute of the *story*, not a measure of *source reliability*.

### 4. Arbitrary agreement threshold

The Arbiter averaged scores if agents were "within 15 points" and picked a winner otherwise. A 14-point gap (e.g., 72 vs 58) was treated as agreement, while a 16-point gap triggered a completely different resolution path. No principled basis for the cutoff.

## Solution: Rubric-Based Deduction Scoring

### Analyst Agent — Content Quality Rubric

Starts at 100. Applies explicit deductions:

| Category | Max Deduction | Triggers |
|----------|--------------|----------|
| Evidence Quality | -30 | No named sources (-15), unsupported claims (-10), unattributed stats (-5) |
| Objectivity | -25 | Single perspective on contested issue (-15), editorializing (-10), sensationalized headline (-5) |
| Attribution | -20 | Vague "sources say" (-10 each, max 2), unverifiable exclusives (-10) |
| Internal Consistency | -15 | Headline/content contradiction (-10), logical gaps (-5) |
| Transparency | -10 | No byline (-5), no/unclear date (-5) |

Minimum score: 10. Returns `trust_deductions` array for full auditability.

### Sentinel Agent — Forensic Penalty Rubric

Starts at 100. Applies forensic penalties:

| Category | Max Deduction | Triggers |
|----------|--------------|----------|
| Propaganda Techniques | -35 | Fear/outrage (-10), false dichotomy (-8), straw man (-8), bandwagon (-5), authority appeal (-5), whataboutism (-5) |
| Linguistic Manipulation | -30 | Loaded language (-10 each, max 3), weasel words (-5 each, max 3), unsupported superlatives (-5) |
| Structural Deception | -20 | Buried lede (-10), misleading headline (-10), cherry-picked data (-10) |
| Omission Signals | -15 | Missing counterargument (-10), missing key context (-10), undisclosed conflicts (-5) |

Sets `linguistic_anomaly_flag = true` when total penalties >= 20. Returns `trust_penalties` array.

### Arbiter Agent — Deduction Validation (not averaging)

The Arbiter no longer uses threshold-based averaging. New method:

1. Start at 100
2. Review each deduction from Analyst's `trust_deductions`
3. Review each penalty from Sentinel's `trust_penalties`
4. **Same issue found by both agents** → apply at full weight
5. **Issue found by only one agent** → apply at 50% weight (rounded)
6. Accept or reject each deduction individually based on article evidence

Returns `accepted_deductions` and `rejected_deductions` arrays with reasoning.

## Source Credibility Formula (Revised)

### Old formula
```
(trust x 0.50) + (anomaly_inverse x 0.25) + (threat_balance x 0.25)
```

### New formula
```
(trust x 0.60) + (anomaly_inverse x 0.25) + (consistency x 0.15)
```

| Component | Weight | What it measures |
|-----------|--------|-----------------|
| Rolling trust score | 60% | Average rubric-based quality (now auditable) |
| Inverse anomaly rate | 25% | How often SENTINEL flags manipulation |
| Scoring consistency | 15% | Low variance = predictable quality (std dev 0 = 100, std dev 30+ = 0) |

### Key changes:
- **Removed threat_balance entirely** — threat level reflects story content, not source quality
- **Added consistency component** — a source that swings between 30 and 90 is less trustworthy than one that consistently scores 65
- **Increased trust weight to 60%** — the rubric-based score is now more meaningful and deserves primary influence
- **Faster warmup** — first 5 articles use alpha=0.4 (prevents anchoring to random first impression), then alpha=0.15

### Consistency formula
```ruby
std_dev = sqrt(trust_score_variance)
consistency = clamp(100 - (std_dev * 3.33), 0, 100)
```

A source with std dev of 10 (normal variation) scores 67/100 on consistency.
A source with std dev of 30+ (wildly inconsistent) scores 0.

## Validation: War Correspondent Scenario

Before (old formula):
- Source covering 90% high-threat topics, trust=78, anomaly_rate=5%
- `threat_balance` = 0.04 → contributes only 1 point
- Grade: ~63 (RELIABLE — barely)

After (new formula):
- Same source: trust=78, anomaly_rate=5%, std_dev=5 (consistent quality)
- Grade: ~83 (TRUSTED)

The source is no longer penalized for covering conflicts.

## Future Considerations

- **Ground truth calibration**: Seed a reference set of known-reliable and known-unreliable sources to validate scoring distribution
- **Deduction drift monitoring**: Track which deduction categories fire most frequently — if one category dominates, the rubric weights may need rebalancing
- **Inter-run stability testing**: Run the same article through the pipeline multiple times and measure score variance (target: < 5 points)
